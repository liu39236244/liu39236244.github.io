 这个错误信息表明：**StarRocks 集群中某个 BE (Backend) 节点的磁盘使用超过了限制**。

## 问题原因

`disk 1967572517290357166 on backend 33543378 exceed limit usage` 说明：

- BE 节点 ID `33543378` 上的某个磁盘空间不足
- 导致无法创建新的 Routine Load 任务

## 解决方案

### 1. 检查 BE 节点磁盘使用情况

```sql
SHOW BACKENDS;
```

查看输出中 `DataUsedCapacity` 和 `TotalCapacity` 列，找到 BE ID `33543378` 对应的磁盘使用率。

### 2. 检查磁盘使用限制配置

```sql
SHOW PROPERTY FOR 'root' LIKE '%storage%';
```

或者查看 BE 配置中的 `storage_flood_stage_usage_percent` 和 `storage_flood_stage_left_capacity_bytes` 参数。

### 3. 临时解决方法

**方案 A：清理历史数据**

```sql
-- 删除不需要的旧分区数据
ALTER TABLE your_table DROP PARTITION p20241101;

-- 或者清理过期的垃圾数据
ADMIN SET FRONTEND CONFIG ("tablet_stat_update_interval_second" = "60");
```

**方案 B：调整磁盘使用阈值（谨慎操作）**

```sql
-- 临时提高磁盘使用率阈值（默认 85%）
ADMIN SET FRONTEND CONFIG ("storage_flood_stage_usage_percent" = "90");
```

**方案 C：扩容磁盘或添加新 BE 节点**

- 如果是生产环境，建议扩容磁盘空间
- 或者添加新的 BE 节点来分担负载

### 4. 检查是否有大量待删除的数据

```sql
-- 查看垃圾回收情况
SHOW PROC '/trash';

-- 手动触发垃圾回收
ADMIN REPAIR TABLE;
```

### 5. 检查 Routine Load 任务占用

由于你的场景是创建 Routine Load 任务失败，可能是：

- 历史数据积累过多
- 某些表的数据没有及时删除
- 副本数设置过高导致空间翻倍占用

**建议排查步骤：**

1. 先执行 `SHOW BACKENDS` 确认具体是哪个 BE 磁盘满了
2. 检查该 BE 上的数据分布：`SHOW PROC '/statistic'`
3. 清理不需要的历史数据
4. 如果是紧急情况，可以临时提高阈值到 90%，但之后必须尽快清理数据或扩容
