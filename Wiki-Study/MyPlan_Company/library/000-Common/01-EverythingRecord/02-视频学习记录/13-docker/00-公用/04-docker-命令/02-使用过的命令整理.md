## 一键启动（docker-compose）

### 目录结构

```
docker/
├── docker-compose.yml        # 编排文件
├── Dockerfile               # 镜像构建
├── docker-entrypoint.sh      # 启动脚本
├── 主节点/config/
│   └── application.yml       # 主节点配置
├── 子节点-1/config/
│   └── application.yml       # 子节点1配置
└── 子节点-2/config/
    └── application.yml       # 子节点2配置
```

### 启动命令

```bash
# 进入 docker 目录
cd docker

# 启动所有节点
docker compose up -d

# 查看日志
docker compose logs -f

# 单独查看某个节点日志
docker compose logs -f beidou-master
docker compose logs -f beidou-slave-1
docker compose logs -f beidou-slave-2

# 停止所有节点
docker compose down

# 重新构建镜像（代码有变更后）
docker build -t beidou-app:latest -f Dockerfile ../
docker compose up -d
```

### 默认端口分配

| 节点    | HTTP | Netty | 说明                                    |
|---------|------|-------|-----------------------------------------|
| 主节点  | 8080 | 9000  | 27500 为子节点长连接端口（对内，无需映射） |
| 子节点1 | 8081 | 9001  |                                         |
| 子节点2 | 8082 | 9002  |                                         |

> 子节点通过 `host.docker.internal` 连接主节点（在 Docker 网络内访问宿主机）。

## Docker 镜像离线迁移

### 导出镜像（源机器）

```bash
# 方式 1：保存为单个 tar 文件（推荐，简单可靠）
docker save beidou-app:latest -o beidou-app-latest.tar

# 方式 2：gzip 压缩（文件更小，传输更快）
docker save beidou-app:latest | gzip > beidou-app-latest.tar.gz

# 方式 3：包含 openjdk 基础镜像一起导出（确保远程机器有基础镜像）
docker save -o beidou-full.tar beidou-app:latest openjdk:17-jdk
```

### 导入镜像（目标机器）

```bash
# 方式 1：直接加载（未压缩）
docker load -i beidou-app-latest.tar

# 方式 2：解压后加载
gunzip -c beidou-app-latest.tar.gz | docker load

# 方式 3：确认加载结果
docker images | findstr beidou
```

### 离线包交付清单

将以下文件拷贝到远程机器即可部署：

```
beidou-deploy/
├── beidou-app-latest.tar.gz   # Docker 镜像（约 300MB 压缩后）
├── docker-compose.yml           # 编排文件
├── 主节点/config/application.yml
├── 子节点-1/config/application.yml
├── 子节点-2/config/application.yml
└── DEPLOY.md                   # 本文档
```

> 镜像只需导出一次，后续修改配置文件后重启容器即可，无需重新导出镜像。

## Java 镜像轻量化

### 当前情况

| 组件           | 大小   | 说明         |
|----------------|--------|--------------|
| jar 包         | 28 MB  | 应用本身     |
| openjdk:17-jdk | 727 MB | 包含完整 JDK |
| 最终镜像       | 783 MB | jar + JDK    |

> **核心问题**：783MB 里 93% 都是 JDK，真正需要的应用代码只有 28MB。

### 方案一：使用 JLink 裁剪 JDK（推荐）

用 `jlink` 把 JDK 裁剪到只包含应用实际用到的模块，从 727MB 减到约 80-120MB：

```dockerfile
# 多阶段构建：先用 Maven 打包，再用 JLink 裁剪 JDK
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /build
COPY pom.xml .
COPY src ./src
RUN mvn clean package -DskipTests -q

# 第二阶段：用裁剪后的 JRE 运行
FROM ubuntu:22.04
RUN apt-get update && apt-get install -y --no-install-recommends \
        openjdk-17-jdk-headless \
    && rm -rf /var/lib/apt/lists/*

# 用 jdeps 分析 jar 依赖哪些模块
RUN /usr/lib/jvm/java-17-openjdk-amd64/bin/jdeps \
        --print-module-deps \
        --ignore-missing-javabean \
        /build/target/beiDou-1.0-SNAPSHOT-exec.jar

# 生成裁剪后的 JRE（示例模块列表，需根据实际 jdeps 输出调整）
RUN /usr/lib/jvm/java-17-openjdk-amd64/bin/jlink \
        --add-modules java.base,java.logging,java.sql,java.naming,java.desktop,java.instrument,java.management,java.security.jgss,java.rmi \
        --output /opt/jre-slim \
        --strip-debug \
        --no-man-pages \
        --no-header-files \
        --compress=2

COPY --from=builder /build/target/beiDou-1.0-SNAPSHOT-exec.jar /app/app.jar
WORKDIR /app
ENV JAVA_HOME=/opt/jre-slim
ENV PATH=$JAVA_HOME/bin:$PATH

# 注意：Spring Boot 3.x 默认使用 GraalVM 原生编译镜像 distroless，
# 实际裁剪大小取决于应用 import 了哪些模块
```

**效果**：
- 基础镜像从 727MB → 约 80-120MB（取决于模块数量）
- 最终镜像约 110-150MB，比现在小 5-7 倍

### 方案二：使用 distroless 或 alpine 基础镜像

```dockerfile
# 使用 distroless（Google 出品的最小化 Java 基础镜像）
FROM gcr.io/distroless/java17-debian11:latest
COPY target/beiDou-1.0-SNAPSHOT-exec.jar /app/app.jar
WORKDIR /app
CMD ["app.jar"]
```

**效果**：distroless 镜像本身约 200-250MB，比 openjdk:17-jdk 小很多。

### 方案三：使用 Spring Boot Layered JAR + 多阶段构建

利用 Spring Boot 3.x 的分层 JAR 特性，在 Docker 中分层缓存，只传输变更的层：

```dockerfile
# pom.xml 中启用分层
# <configuration>
#   <layers>
#     <enabled>true</enabled>
#   </layers>
# </configuration>

FROM eclipse-temurin:17-jdk-alpine AS build
WORKDIR /app
COPY target/beiDou-1.0-SNAPSHOT-exec.jar app.jar
RUN java -Djarmode=layertools -jar app.jar extract

FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY --from=build /app/dependencies/ ./
COPY --from=build /app/spring-boot-loader/ ./
COPY --from=build /app/snapshot-dependencies/ ./
COPY --from=build /app/application/ ./
ENTRYPOINT ["java", "org.springframework.boot.loader.launch.JarLauncher"]
```

**效果**：不改代码，利用 Docker 缓存机制加速构建。

### 总结对比

| 方案                 | 镜像大小   | 复杂度 | 推荐度   |
|----------------------|------------|--------|----------|
| 当前（openjdk:17-jdk） | 783 MB     | 简单   | 基准     |
| 方案一（JLink 裁剪）   | 110-150 MB | 高     | **推荐** |
| 方案二（distroless）   | 250-300 MB | 低     | 推荐     |
| 方案三（分层 JAR）     | 不减小     | 中     | 加速构建 |

> 如果追求极致轻量化，推荐 **方案一（JLink）**，可以裁掉 80% 的镜像体积。如果追求简单，推荐 **方案二（distroless）**，只需改一行 FROM。

## 常见问题

**Q: 构建报错 `target/beiDou-1.0-SNAPSHOT-exec.jar not found`**
A: 先执行 `mvn clean package -DskipTests`

**Q: 子节点连不上主节点？**
A: 子节点配置中 `master.host` 应设为 `host.docker.internal`（Docker 网络内访问宿主机）

**Q: 容器启动后无法访问宿主机目录？**
A: Windows 下路径用正斜杠 `D:/data/...`，不要用反斜杠

**Q: 想修改端口怎么办？**
A: 修改对应节点 `config/application.yml` 中的 `server.port`，同时更新 `docker-compose.yml` 中的端口映射

**Q: 想只跑单个节点？**
A: `docker compose up -d beidou-master` 即可只启动主节点
