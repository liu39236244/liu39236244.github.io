你执行 `nmcli connection modify` 时没有加 `+` 号，按理说是**替换**操作，`192.168.5.202` 不应该出现。它之所以还在，最可能的原因是：**NetworkManager 从别的地方（比如 DHCP）又把它拿回来了，盖过了你手动设置的 DNS。**

你之前看到的 `192.168.5.202` 很可能就是通过 DHCP 自动下发的。当你只设置 `ipv4.dns` 时，如果没有明确告诉 NetworkManager“不要理会 DHCP 给的 DNS”，它可能会把两者合并，或者在某些情况下让 DHCP 的 DNS 优先。

### 怎么让 `192.168.5.202` 彻底消失

你需要多做一步：**明确忽略 DHCP 自动获取的 DNS**，然后再重新激活连接。

```bash
# 1. 明确忽略 DHCP 下发的 DNS
nmcli connection modify "System eth0" ipv4.ignore-auto-dns yes

# 2. 再次确认手动 DNS 设置（确保只有你想要的）
nmcli connection modify "System eth0" ipv4.dns "114.114.114.114 223.5.5.5"

# 3. 重新激活连接让配置彻底生效
nmcli connection down "System eth0"
nmcli connection up "System eth0"
```

执行完再 `cat /etc/resolv.conf`，`192.168.5.202` 应该就没了。

### 如果还不行

可以检查一下连接配置里实际存了什么：
```bash
nmcli -f ipv4.dns,ipv4.ignore-auto-dns connection show "System eth0"
```
如果 `ipv4.dns` 里确实只有那两个公共 DNS，但 `resolv.conf` 还是多出来一个，那可能是其他连接（比如另一个自动激活的网卡）在往里面写 DNS。可以用 `nmcli device show eth0 | grep DNS` 看看当前设备实际生效的 DNS 列表，交叉验证一下。

另外，如果 `192.168.5.202` 是你内网必需的 DNS（用来解析内网主机名），那把它保留在列表最后其实是合理的。但如果你确认不需要它，上面 `ignore-auto-dns yes` 这一步就是关键。
