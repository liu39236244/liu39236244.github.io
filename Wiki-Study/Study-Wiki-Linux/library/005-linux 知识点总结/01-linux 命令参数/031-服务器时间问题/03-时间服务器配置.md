### 让配置生效

修改 `/etc/chrony.conf` 后，重启 chronyd 服务：

```bash
systemctl restart chronyd
```

然后等几秒，让 chrony 有时间去解析域名、建立连接。

### 验证是否生效

**1. 看源列表和同步状态**
```bash
chronyc sources -v
```
- 如果列出源，且行首是 `^*`，说明已同步成功。
- 如果列出源但行首是 `^?`，说明源被识别到了，但连不上（网络或 DNS 问题）。
- 如果 `Number of sources = 0`，说明配置没被加载（比如域名解析失败，chrony 直接忽略了这些行）。

**2. 看整体同步状态**
```bash
chronyc tracking
```
重点看两行：
- `Leap status`：变成 `Normal` 才算同步正常。
- `System time`：偏差应该在毫秒级以内。

**3. 确认时间本身对不对**
```bash
date
```
和标准时间对比一下，偏差在可接受范围内即可。如果偏差还很大（比如几分钟），且源已经是 `^*`，可以强制步进一次：

```bash
chronyc makestep
```

### 关键提醒

如果你恢复的是**域名源**（比如 `ntp.aliyun.com`），而 DNS 还没完全修好，chrony 重启后可能再次出现 `Number of sources = 0`。这种情况下，要么等 DNS 修好再恢复域名配置，要么继续保留 IP 源（`203.107.6.88`）作为兜底。验证时先看 `chronyc sources -v` 有没有源，这是第一道关。
